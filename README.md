# Clinical_Metagenomics_pipeline-
Bioinformatics pipeline for the detection and characterization of potential pathogens in biological samples from patients with undiagnosed conditions using targeted sequencing and whole-genome sequencing (WGS) data.

---

## Overview

This repository provides an end-to-end workflow integrating laboratory
procedures, sequencing, and bioinformatics analysis for the detection
and characterization of potential pathogens in biological samples from
patients with undiagnosed conditions.

The workflow combines targeted sequencing and whole-genome sequencing
approaches with computational methods for quality control, taxonomic
classification, host-read removal, de novo assembly, sequence
identification, read mapping, abundance estimation, taxonomic
annotation, visualization, and comparison with negative controls.

## Laboratory Workflow

### Nucleic Acid Extraction

DNA and/or RNA should be extracted from the biological samples using commercial nucleic acid extraction kits. Whenever possible, kits that have been validated for the specific sample type should be used, particularly for complex matrices such as tissue samples, which may require additional processing and optimization.

### Library Preparation

For pathogen screening, we validated targeted sequencing workflows using pathogen detection panels, including Illumina DNA Prep with enrichment using RPIP, UPIP, and VSP (Illumina).

For whole-genome sequencing (WGS), library preparation was validated using the Illumina DNA Prep and QIAseq FX DNA library preparation kits.

## Requirements

### Operating System

The pipeline was developed and tested in a Linux environment and is intended to run on Linux-based systems.

### Environment Management

[Micromamba](https://mamba.readthedocs.io/en/latest/user_guide/micromamba.html) is recommended for environment management and reproducible installation of the required software.

The following command-line tools are required:

| Kraken2  | Initial taxonomic classification                            |
| Krona    | Interactive taxonomic visualization                         |
| Bowtie2  | Host-read removal                                           |
| SAMtools | BAM processing, filtering, conversion, and FASTQ extraction |
| SeqKit   | FASTQ statistics                                            |

* pandas
* numpy
* plotly
* openpyxl

The pipeline also uses local Python modules for taxonomic processing:

* `utils.taxonomy_utils`
* `utils.constants`

These modules must be included in the repository under the `utils/` directory.

### Reference Databases

The pipeline requires the following reference resources:

* Kraken2 taxonomic database
* Bowtie2 host reference index
* DIAMOND protein reference database
* Krona taxonomy database

Reference database paths are configured within the pipeline scripts and should be adapted to the local installation.

## Bioinformatics analysis 

The bioinformatics workflow starts from paired-end raw FASTQ files generated by targeted or whole-genome sequencing. Samples and negative controls are processed through the same analytical workflow, allowing downstream comparison of microbial profiles between samples and controls.

### Downloading FASTQ Files

If the FASTQ files have not been downloaded yet, they can be retrieved from **Illumina BaseSpace** using the BaseSpace Command Line Interface (CLI):

```bash
bs download project -i <ProjectID> -o <output_directory> --extension=fastq.gz
```

Replace `<ProjectID>` with the BaseSpace project ID and `<output_directory>` with the directory where the FASTQ files should be saved.

The downloaded files should then be organized according to the input directory structure expected by the pipeline.

### Output folder
All analysis steps generate sample-specific outputs under:

```text
outputs/<SAMPLE>/
```

### Step 0 — Prepare the Analysis Structure

Before starting the analysis, organize the FASTQ files into separate directories for samples and controls:

```text
fastq/
├── samples/
└── controls/
```

The preparation script creates the required output directories for each sample.

```bash
bash scripts/00_prepare_samples.sh
```

---

### Step 1 — Read Quality Control

[Fastp](https://github.com/OpenGene/fastp) is used for initial quality control and adapter trimming of paired-end sequencing reads. Reads are processed using quality filtering with a minimum Phred quality score of 30.

```bash
bash scripts/1-fastp.sh
```

Output:

```text
outputs/<SAMPLE>/1-fastp/
├── <SAMPLE>.cleaned_R1.fq.gz
├── <SAMPLE>.cleaned_R2.fq.gz
├── <SAMPLE>.fastp.html
└── <SAMPLE>.fastp.json
```

---

### Step 2 — Initial Taxonomic Screening

[Kraken2](https://github.com/DerrickWood/kraken2) is used for an initial taxonomic classification of the sequencing reads.

```bash
bash scripts/2-kraken.sh
```

The classification is performed against the configured Kraken2 reference database.

Output:

```text
outputs/<SAMPLE>/2-kraken2/
├── <SAMPLE>.kraken
└── <SAMPLE>.kraken_report
```

---

### Step 3 — Kraken2 Taxonomic Visualization

[Krona](https://github.com/marbl/Krona) is used to generate an interactive visualization of the taxonomic classification obtained with Kraken2.

```bash
bash scripts/3-krona.sh
```

Output:

```text
outputs/<SAMPLE>/3-krona/
├── <SAMPLE>.input.krona
└── <SAMPLE>.krona.html
```

---

### Step 4 — Host Read Removal

[Bowtie2](https://github.com/BenLangmead/bowtie2) is used to identify and remove reads originating from the host genome.

The workflow aligns the cleaned reads against a configured host reference genome and extracts the non-host reads for downstream metagenomic analysis.

```bash
bash scripts/4-bowtie_host_removal.sh
```

Output:

```text
outputs/<SAMPLE>/3-bowtie2/
├── <SAMPLE>.un.R1.fq.gz
├── <SAMPLE>.un.R2.fq.gz
├── <SAMPLE>_sorted.bam
├── <SAMPLE>_sorted_unmapped.bam
├── <SAMPLE>_sorted_mapped.bam
└── <SAMPLE>.stats.nonhosts.tsv
```

---

### Step 5 — De novo Metagenomic Assembly

[MEGAHIT](https://github.com/voutcn/megahit) is used to perform de novo assembly of the non-host paired-end reads into metagenomic contigs.

```bash
bash scripts/5-megahit.sh
```

The main output is:

```text
outputs/<SAMPLE>/4-megahit/<SAMPLE>/final.contigs.fa
```

This FASTA file contains the assembled contigs used for downstream sequence identification.

---

### Step 6 — Read Mapping and Abundance Estimation

[CoverM](https://github.com/wwood/CoverM) is used to map sequencing reads against the assembled contigs and estimate contig-level abundance and coverage metrics.

```bash
bash scripts/6-coverm.sh
```

The workflow calculates:

* Covered fraction
* Read count
* Reads per base
* Mean coverage
* RPKM
* TPM

Output:

```text
outputs/<SAMPLE>/5-coverm/
└── <SAMPLE>_reads_count.tsv
```

---

### Step 7 — CoverM Summary

The CoverM output is processed using Python to generate a simplified CSV table containing read counts and relative composition.

```bash
python3 scripts/7-coverm_summary.py
```

Output:

```text
outputs/<SAMPLE>/5-coverm/
└── <SAMPLE>_reads_count.csv
```

---

### Step 8 — Protein-Level Contig Identification

[DIAMOND](https://github.com/bbuchfink/diamond) BLASTX is used to identify potential microbial sequences by comparing translated metagenomic contigs against a protein reference database.

```bash
bash scripts/8-diamond.sh
```

The analysis records sequence identity, alignment information, coverage, E-value, bitscore, taxonomic identifiers, and sequence descriptions.

Output:

```text
outputs/<SAMPLE>/6-diamond/
└── <SAMPLE>.diamond_blastx.txt
```

A specialized DIAMOND database can also be used for targeted screening of specific pathogen groups when required.

---

### Step 9 — Taxonomic Annotation

The DIAMOND results are processed to retrieve the taxonomic classification associated with detected sequences and to generate the input required for downstream Krona visualization.

```bash
python3 scripts/9-taxonomy.py
```

Output:

```text

└── krona_input.tsv
```


### Step 10 — Integrated Reports

## Interpretation & Limitations

### Interpretation

The pipeline integrates taxonomic classification, host-read removal, de novo assembly, read-to-contig mapping, protein-level similarity searches, and control-based comparison to support the identification and characterization of potential pathogens in clinical samples.

Candidate microorganisms should be evaluated using multiple complementary pieces of evidence, including:

* **Taxonomic consistency:** agreement between Kraken2 classification and DIAMOND-based taxonomic assignment.
* **Read abundance:** number and relative proportion of reads assigned to a taxon, as estimated from read-to-contig mapping.
* **Genome representation:** presence of assembled contigs and their corresponding read coverage.
* **Sequence similarity:** identity, alignment coverage, and significance of DIAMOND matches.
* **Control comparison:** comparison with negative controls to identify taxa that may also be present in controls or background samples.
* **Biological plausibility:** consistency between the detected microorganism, the sample type, and the patient's clinical context.

Taxa detected at low abundance, supported by limited sequence coverage, or also detected in negative controls should be interpreted cautiously. Results should be considered as evidence for further investigation rather than as a standalone clinical diagnosis.

### Limitations

This workflow has several limitations that should be considered when interpreting the results:

* **Low-abundance organisms may be missed.** Pathogens present at very low concentrations may not generate sufficient sequencing reads for reliable detection.
* **Host DNA/RNA can dominate sequencing data.** Although host-read removal is performed using Bowtie2, residual host sequences may remain and reduce the fraction of reads available for microbial analysis.
* **Database dependency.** Taxonomic classification and DIAMOND-based identification depend on the organisms and sequences represented in the reference databases. Novel, divergent, or poorly represented organisms may be missed or incorrectly assigned.
* **Taxonomic misclassification is possible.** Closely related organisms may produce ambiguous or misleading taxonomic assignments, particularly when only short or conserved sequence regions are available.
* **Assembly limitations.** De novo assembly may fail for low-abundance organisms or highly fragmented sequencing data, resulting in incomplete or absent contigs.
* **Contamination and background DNA/RNA.** Environmental, reagent-derived, laboratory, or index-related contamination can produce microbial sequences that are not associated with the patient's condition.
* **Negative controls are essential but not sufficient.** Comparison with negative controls can help identify background taxa, but the absence of a taxon from a control does not by itself establish clinical relevance.
* **Read abundance is not equivalent to pathogen load.** Read counts and relative abundance can be affected by sequencing depth, genome size, extraction efficiency, library preparation, and other technical factors.
* **Detection does not establish causality.** Identification of microbial sequences does not demonstrate that the organism is responsible for the patient's clinical presentation.
* **Clinical interpretation requires additional evidence.** Candidate pathogens should be evaluated together with clinical, epidemiological, laboratory, and, when appropriate, orthogonal molecular or microbiological evidence.

### Recommended Evidence Review

For candidate pathogens, interpretation should therefore consider the combined evidence generated by the workflow rather than relying on a single metric. A candidate supported by consistent taxonomic assignment, sufficient read abundance and genome coverage, sequence-level evidence, and absence or low representation in negative controls provides a stronger basis for follow-up investigation.

Final clinical interpretation should be performed by qualified healthcare and laboratory professionals in conjunction with the patient's clinical information.
